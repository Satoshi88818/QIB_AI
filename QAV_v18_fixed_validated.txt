# QIB AI Verifier v18 — fixed, tested and validated core **Status:** the Rust core and the TLA+ model were compiled, executed and model-checked in a sandbox (Rust 1.75, Java 21, TLC 2026.11.03). The numbers below are from those runs, not estimates. Section 5 lists what was **not** built or verified, so please read it before relying on this. ## 1. What this is A pure-Rust library crate (`qib-verifier`) that implements the safety gate from v17 spec, with the problems found in the review fixed. It has no Python bindings, no async prober and no exporter (see §5). The design splits into two handles returned by `Verifier::build`: * `DataPlane` is what the AI controller may call: observe, ingest signed probes, compare, route, health. * `ControlPlane` is operator-only: reset breaker, lift quarantine/zone, set conservative mode, reload config. It is not `Clone`, and every action is written to the audit log **before** it takes effect (fail closed). ## 2. Not built, not verified, and known limits **Not built.** PyO3/Python bindings and `.pyi` stubs; Prometheus exporter; async (tokio) mesh prober (the crate exposes `take_mesh_probe_request` and `ingest_probe`, so any executor can drive it); `notify`-based file watcher (`reload_config` takes text and is validated and audited; a polling or watcher loop is a thin wrapper); the ZK/SNARK roadmap. Nothing in these layers was tested because they do not exist here. **Not run.** Kani (the proofs were replaced by property tests on the real functions, which sample inputs rather than prove all inputs); Miri; `clippy` and `rustfmt` (not installed in the sandbox); the TLA+ ↔ Rust refinement. Tested only on Rust 1.75 / Linux x86-64. **Threat-model limits.** * The `DataPlane`/`ControlPlane` split is a type-level guarantee **inside one process**. It stops accidental misuse, but a compromised AI process that shares memory with the operator handle is not stopped. For a real boundary, put `ControlPlane` behind a separate authenticated process or channel. * `compare_and_audit` and probes are only as trustworthy as their source. The AI controller must not supply the "actual" fidelity it is being audited against. The probe agent's Ed25519 **private key** must never be reachable from the AI process. * The static fallback path (used when AI mode finds no admissible path) ignores AI beliefs but still honours quarantine. If every route is quarantined you get `NoPath`, by design. ## 6. Behaviour changes that need an owner's sign-off 1. **Quarantine trigger:** a failed physical probe quarantines a link if the twin had predicted ≥ 0.90 (the probe pass threshold). v17 used 0.99, which let a link predicted at 0.95 fail a physical probe without quarantine. A link the twin already distrusts (< 0.90) is not quarantined but its cost already reflects it. 2. **Uncertainty meaning:** it is now the predictive std (not std-error), and is 1.0 until 5 samples. Existing thresholds (0.05, 0.15, 0.08) keep their numbers but not their old statistical meaning, so re-baseline them on real data. 3. **Strict input validation:** observations outside [0, 1] are rejected rather than clamped. 4. **Drift/overconfidence** uses mean std instead of entropy; its thresholds also need tuning on real data. 5. **Escalation:** stage 3 → 4 trips the breaker; the breaker is a latch until `reset_breaker`. ## 7.
